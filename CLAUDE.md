# ИИ-практики из Беларуси

## Карта проекта

**Что это.** Лендинг для белорусских собственников классического бизнеса, которые хотят внедрить ИИ у себя, но не знают, к кому обратиться. Страница сводит их с практиками — выпускниками курса Анатоля «Claude Code: от нуля до уверенной работы», которые уже автоматизируют процессы руками. Единственное действие на странице — написать Анатолю в Telegram (@ahtlv); первых клиентов он сводит с практиками вручную. Задача страницы — проверить спрос. Следующий шаг (MVP) — «Разбор процесса за минуту»: собственник выбирает свой процесс, отвечает на пару вопросов и получает честный разбор по заготовленным правилам (без изображения ИИ) плюс реальный пример Анатоля. Подробно — в `docs/superpowers/specs/`.

**Что где лежит.**
- `index.html` — весь лендинг в одном файле, стили внутри, без внешних загрузок.
- `portrait.png` — фото на странице.
- `tests/test_page.py` — проверки страницы (`python3 -m unittest discover tests`).
- `docs/superpowers/specs/` — документы дизайна: зачем, цели, анти-цели, ограничения.
- `docs/superpowers/plans/` — планы реализации.
- `docs/screens/` — скриншоты страницы на телефоне и десктопе.
- `docs/agents/` — настройки для скиллов: где задачи, какие метки, где словарь проекта.

**Как сайт публикуется.** GitHub Pages из этого репозитория (ahtlv/ai-praktiki). После `git push` в основную ветку сайт обновляется сам через минуту-две: https://ahtlv.github.io/ai-praktiki/. Сервера нет — только HTML, CSS и JS в браузере.

**Как мы работаем.** Работа нарезана на задачи в GitHub Issues. Одна задача = одна новая сессия Claude: открыть задачу (`gh issue view <номер>`), сделать, проверить, закоммитить, запушить и закрыть задачу. Не тащить несколько задач в одну сессию.

## Agent skills

### Issue tracker

Задачи живут в GitHub Issues репозитория ahtlv/ai-praktiki, работаем через `gh`. See `docs/agents/issue-tracker.md`.

### Triage labels

Стандартные метки: needs-triage, needs-info, ready-for-agent, ready-for-human, wontfix. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: один `GLOSSARY.md` и `docs/adr/` в корне (создаются по мере надобности). See `docs/agents/domain.md`.
